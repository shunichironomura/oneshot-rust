上限つきの待ち行列（bounded blocking queue）は、スレッドどうしで要素を受け渡すための仕組みです。
生産者は `push` で要素を入れ、消費者は `pop` で入れた順に取り出します。どちらも、できることがない間は待ちます。
`BoundedQueue<T>` を実装してください。フィールドは自由に決めてください。`std` のものは何を使っても
構いません（`std::sync::Condvar` を使うと、ほかのスレッドに起こされるまでスレッドを眠らせておけます）。

```rust
pub struct BoundedQueue<T> {
    // フィールドは自由に決める
}

impl<T> BoundedQueue<T> {
    pub fn new(capacity: usize) -> Self;
    pub fn push(&self, item: T) -> Result<(), T>;
    pub fn pop(&self) -> Option<T>;
    pub fn close(&self);
    pub fn len(&self) -> usize;
}
```

- `new(capacity)` は、空で開いている待ち行列を作ります。入る要素は最大 `capacity` 個です。
  `capacity` は 1 以上です。
- `push(item)` は `item` を待ち行列の末尾に追加して `Ok(())` を返します。待ち行列がいっぱいの間は、
  空きができるまで待ちます。
- 待ち行列が閉じていれば、`push` はすぐに `Err(item)` を返し、要素を追加しません。空きがあっても同じです。
  待っている間に待ち行列が閉じられた `push` も、待つのをやめて `Err(item)` を返します。
  閉じた待ち行列に要素が追加されることはありません。
- `pop()` は待ち行列の先頭の要素を取り除いて `Some(item)` を返します。要素は追加された順に出てきます。
  待ち行列が空で開いている間は、要素が入るか、待ち行列が閉じられるまで待ちます。
- 閉じたときに待ち行列に入っていた要素は、閉じた後も取り出せます。`pop` が `None` を返すのは、
  待ち行列が閉じていて空のときだけで、そのときはすぐに返します。
- `close()` は待ち行列を閉じます。閉じた待ち行列が再び開くことはありません。
  閉じた待ち行列をもう一度閉じても何も起きません。
- `len()` は、いま待ち行列に入っている要素の個数を返します。`capacity` を超えることはありません。
- 待っている呼び出しは、先に進めるのに眠り続けてはいけません。待っている `push` は空きができたことに、
  待っている `pop` は要素が入ったことに、待っているすべての呼び出しは待ち行列が閉じられたことに
  気づく必要があります。
- ハーネスは 1 つの `&BoundedQueue<T>` を複数のスレッドで共有します（`std::thread::scope` を使います）。
  そのため `BoundedQueue<T>` は、`T` が `Send` なら、複数のスレッドから同時に使えなければなりません。
  `T` は `Clone` や `Copy` や `Debug` を実装しているとは限りません。
- ハーネスが、起こりえないことを待つことはありません。たとえば、この先どのスレッドも `push` も `close` も
  しない空の待ち行列から `pop` することはありません（すべてのスレッドが永遠に待つと、Miri はデッドロックを
  報告します）。

シグネチャは変えないでください。

### 例

```rust
let q = BoundedQueue::new(2);
q.push(1)    // Ok(())
q.push(2)    // Ok(())。これでいっぱいなので、もう 1 つ push すると待つことになる
q.len()      // 2
q.pop()      // Some(1)
q.push(3)    // Ok(())
q.close();
q.push(4)    // Err(4)。閉じている
q.pop()      // Some(2)。すでに入っている要素は取り出せる
q.pop()      // Some(3)
q.pop()      // None。閉じていて空
```

容量 2 の待ち行列に、メインスレッドが 100 から 104 を、別のスレッドが 200 から 204 を `push` し、
さらに 2 つのスレッドが `None` を受け取るまで `pop` を続けます。両方のスレッドがすべて `push` し終えたら、
メインスレッドが待ち行列を閉じます。どの `push` も `Ok(())` を返し、どの要素もちょうど 1 回ずつ取り出されます。
また、取り出す側のどのスレッドにも、入れる側のそれぞれのスレッドの要素は、入れた順に届きます。
