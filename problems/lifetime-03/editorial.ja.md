参照の引数が 2 つあると、要素の `&str` がどちらを借りているかをコンパイラは推測できないので、ライフタイムに名前を付けます。
行は `text` から来るので、`text: &'a str` と `Item = &'a str` です。`pattern` は最初に所有権を持つ `String` に
コピーされるので、イテレータは `pattern` をまったく借用しません。

ただ、それだけでは足りません。Rust 2024 では、返り値の `impl Trait` は**スコープ内のすべてのライフタイムをキャプチャ**します。
`pattern` の無名のライフタイムも含まれるので、呼び出し側はイテレータと同じだけ `pattern` を生かしておく必要があり、
`pattern` を先に破棄するハーネスはコンパイルできません。`+ use<'a>` は隠れた型が使ってよいライフタイムを明示的に列挙するもので、
これを付けると関数から戻った時点で `pattern` の借用は終わります。

古いエディションでの定番だった `+ 'a` はここでは役に立ちません。イテレータが少なくとも `'a` の間は有効であることを約束するだけで、
`pattern` のライフタイムはキャプチャされたままだからです。

### 別解

2 つ目のライフタイムにも名前を付けると、それを `use<..>` から外していることがはっきりします。

```rust
pub fn matching_lines<'a, 'p>(
    text: &'a str,
    pattern: &'p str,
) -> impl Iterator<Item = &'a str> + use<'a> {
    let pattern = pattern.to_lowercase();
    text.lines()
        .filter(move |line| line.to_lowercase().contains(&pattern))
}
```

`use<..>` にはスコープ内の**型**パラメータをすべて書く必要があり、省略できるのはライフタイムだけである点に注意してください。
