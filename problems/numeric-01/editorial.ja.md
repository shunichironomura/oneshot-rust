問題は複数あり、コンパイラは一度に全部を報告しません。先に型のエラーが出て、`mut` の付け忘れは型を直した後で
初めて報告されます。

- `sum += values[i]` は `i64` に `i32` を足しています。Rust は整数型を暗黙に変換しないので、`i64::from(...)`
  （または `as i64`）で広げる必要があります。`sum -= ...` も同じです。
- `sum / window` は `i64` を `usize` で割っているので、これも型が合いません。型をそろえても整数の割り算では小数部が
  切り捨てられますし、`averages` は `Vec<f64>` です。先に両辺を `f64` にします（`sum as f64 / window as f64`）。
- `sum` はループの中で変更するので `let mut` で宣言します。

`sum` は `i64` のままにしてください。`i32` に変えてもコンパイルは通りますが、`i32::MAX` に近い値を 2 つ足すと
オーバーフローし、デバッグビルドではパニックします。

`values[i]` の添字はこのままで問題ありません。`i` は `0..values.len()` から来るので `usize` です。

### 別解

`i64::from` は情報を失わない変換で、失う可能性がある組み合わせではコンパイルエラーになるので、広げる変換には
`as` より安全です。`f64` にするには `as` を使うのが普通です。連続する `window` 個の要素を順に返す `windows` を
使うと次のように書けます。

```rust
pub fn moving_average(values: &[i32], window: usize) -> Vec<f64> {
    if window == 0 {
        return Vec::new();
    }
    values
        .windows(window)
        .map(|w| w.iter().map(|&x| i64::from(x)).sum::<i64>() as f64 / window as f64)
        .collect()
}
```

`windows` はサイズ `0` でパニックするので先にチェックしています。`window` がスライスより長いときは何も返しません。
毎回合計を計算し直しますが、短い入力なら問題ありません。
