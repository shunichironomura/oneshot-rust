通常の文字列リテラルでは `\` はエスケープの始まりで、使えるエスケープは `\n`、`\r`、`\t`、`\\`、`\0`、
`\'`、`\"`、`\x41`、`\u{...}` だけです（ほかに、行末の `\` は改行とその後に続く空白を読み飛ばします）。
`\d` や `\.` はエラーになり、型検査より前、ソースを読み込む段階で見つかります。生文字列 `r"..."` には
エスケープがまったくないので、バックスラッシュはただのバックスラッシュです。正規表現や Windows のパスを
書くにはこれがいちばん簡単です。

こうした文字列で、報告されたエスケープだけを直すのは危険です。リテラルとして正しいものには、コンパイラは
文句を言えません。`\n` と `\t` は正しいエスケープなので、`"C:\new"` はコンパイルが通りますが、改行を
含んでしまいます。

### 別解

多くの言語と同じように、通常のエスケープでも書けます。バックスラッシュをすべて 2 つ重ねます。

```rust
pub fn number_pattern() -> &'static str {
    "\\d+\\.\\d+"
}
```
