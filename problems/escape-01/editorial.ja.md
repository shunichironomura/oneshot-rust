ここでは 4 種類のリテラルの規則が破られています。コンパイラはほとんどの間違いを一度に報告します。
どれも型検査より前、ソースを読み込む段階で見つかるからです。しかし、リテラルとして正しいものには
文句を言えません。本当の罠はそこにあります。

- 通常の文字列リテラルでは `\` はエスケープの始まりで、使えるエスケープは `\n`、`\r`、`\t`、`\\`、`\0`、
  `\'`、`\"`、`\x41`、`\u{...}` だけです。`\d` や `\.` はエラーになります。`windows_path` でコンパイラが
  報告するのは `\d` だけです。`\n` と `\t` は改行とタブを表す正しいエスケープだからです。`\d` だけを直すと
  コンパイルは通りますが、`C:`、改行、`ew`、タブ、`able\data.txt` の 19 文字が返ります。
  生文字列 `r"..."` にはエスケープがまったくないので、バックスラッシュはただのバックスラッシュです。
  正規表現や Windows のパスを書くにはこれがいちばん簡単です。
- 通常のリテラルは `"` で終わるので、`"{"name": ...` はリテラル `"{"` と、パーサが想定していない
  トークンの並びになります（閉じ引用符にくっついた単語はリテラルのサフィックスとして読まれるので、
  `"{"name` で 1 つのトークンになり、エラーは次のトークン `": "Ferris` を指します）。
  引用符をそれぞれ `\"` とエスケープするか、`"` を含められる生文字列 `r#"..."#` を使います。
- 生文字列 `r#"..."#` は最初の `"#` で終わりますが、`"#rust"` にはそれが含まれています。`#` をもう 1 つ
  増やします。`r##"..."##` は `"##` が来るまで終わらず、中身に `"##` はありません。生文字列の中では
  バックスラッシュも役に立ちません。`r#"... "\#rust" ..."#` はコンパイルが通りますが、
  バックスラッシュがそのまま残ります。
- `str` は常に正しい UTF-8 なので、`str` のリテラルで使える `\x` エスケープは `\x7F` までです。`\u{89}` は
  コンパイルが通りますが、これは文字 U+0089 で、UTF-8 では `0xC2 0x89` の 2 バイトになるため、
  結果は 9 バイトになってしまいます。バイト文字列 `b"..."` は文字ではなくバイトの並びで、
  `\x00` から `\xFF` まで書けます。型は `&'static [u8; 8]` で、返り値の型 `&'static [u8]` に型強制されます。
  `.as_bytes()` も消してください。これは `str` のメソッドで配列にはないので、`b"...".as_bytes()` は
  コンパイルが通りません。

### 別解

どの値も、多くの言語と同じように通常のエスケープで書けます。バックスラッシュはすべて 2 つ重ね、
引用符はすべてエスケープします。バイトは `u8` リテラルの配列でも書けます。`b'P'` は ASCII 文字 `P` の
バイトです。定数だけからなる配列に `&` を付けると `'static` な値に昇格されるので、`&'static [u8]` として
返せます。

```rust
pub fn number_pattern() -> &'static str {
    "\\d+\\.\\d+"
}

pub fn windows_path() -> &'static str {
    "C:\\new\\table\\data.txt"
}

pub fn json_snippet() -> &'static str {
    "{\"name\": \"Ferris\", \"tags\": [\"crab\"]}"
}

pub fn hashtag_quote() -> &'static str {
    "He said \"#rust\" twice"
}

pub fn png_magic() -> &'static [u8] {
    &[0x89, b'P', b'N', b'G', b'\r', b'\n', 0x1A, b'\n']
}
```

生文字列とバイト文字列は組み合わせられます。`br"C:\new"` はエスケープのないバイト文字列です。
