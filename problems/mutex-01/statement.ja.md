次のコードはコンパイルが通りますが、実行するといつまでも終わりません。Miri は
「the evaluated program deadlocked」（デッドロックした）というエラーで実行を止めます。

`Memo` は、再帰的な計算や並行な計算のために計算済みの値をキャッシュし（メモ化）、
処理を待つキーのキューも持っています。実装はすべてエディタに入っています。

```rust
pub struct Memo {
    cache: Mutex<BTreeMap<u64, u64>>,
    queue: Mutex<Vec<u64>>,
    misses: AtomicUsize,
}

impl Memo {
    pub fn new() -> Self;
    pub fn get_or_compute(&self, key: u64, f: impl FnOnce(&Memo, u64) -> u64) -> u64;
    pub fn misses(&self) -> usize;
    pub fn schedule(&self, key: u64);
    pub fn run_all(&self, f: impl Fn(&Memo, u64) -> u64) -> Vec<(u64, u64)>;
}

pub fn fib(m: &Memo, n: u64) -> u64 {
    m.get_or_compute(n, |m, n| if n < 2 { n } else { fib(m, n - 1) + fib(m, n - 2) })
}
```

- `Memo::new()` は、キャッシュした値がなく、キューが空で、ミス回数が 0 のメモを作ります。
- `get_or_compute(key, f)` は、`key` の値がキャッシュにあれば、`f` を呼ばずにその値を返します。
  なければ（ミス）、`f(self, key)` を 1 回呼び、`f` が返した値を `key` の値としてキャッシュし、
  ミス回数に 1 を足して、その値を返します。キャッシュは 1 つのメモに 1 つだけで、
  `fib` や `run_all` を通した呼び出しも含め、すべての呼び出しで共有します。
- `f` は実行中に、受け取ったメモを使うことがあります。ほかのキーについての `get_or_compute`
  （`fib` がそうしています）、`schedule`、`misses` を呼ぶことがあります。計算中のキー自身を
  求めることはなく、`run_all` を呼ぶことも、パニックすることもありません。
- `misses()` はミス回数を返します。
- `schedule(key)` は `key` をキューに追加します。同じキーが何度キューに入ってもかまいません。
- `run_all(f)` はキューが空になるまで処理を続け、処理したキー 1 つにつき 1 つの組
  `(key, value)` を処理した順に並べて返します。1 回の処理では、次のことをこの順に行います。
  1. 最後に追加されたキー `k` をキューから取り出します（後入れ先出し）。
  2. `get_or_compute` で値 `v` を得ます。ミスのときは、メモと `k` を渡して `f` を呼び、
     値を計算します。
  3. `(k, v)` を結果の末尾に追加します。
  4. `k > 1` なら、`k / 2`（切り捨て）を `schedule` します。

  `run_all` の実行中に追加されたキーは、`f` が追加したものも含め、同じ呼び出しの中で処理します。
  キューが空なら、`run_all` は空の `Vec` を返します。
- ハーネスは、1 つのメモを複数のスレッドで共有します（`std::thread::scope` を使います）。
  各スレッドは `get_or_compute` を（直接、`fib` を通して、または `run_all` を通して）同時に
  呼ぶことがありますが、キューを使うのは一度に 1 つのスレッドだけです。複数のスレッドが同じキーで
  同時にミスした場合は、それぞれが計算してミスを数えてもかまいません。ハーネスは、
  そのような同時の呼び出しが返す値は確認しますが、ミスを何回数えたかは確認しません。

説明どおりに動くようにコードを直してください。`Memo` のフィールド、公開されているシグネチャ、
`fib` は変えないでください。非公開のヘルパーは追加してかまいません。

### 例

```rust
let m = Memo::new();
fib(&m, 10)   // 55
m.misses()    // 11：fib(0) から fib(10) までをそれぞれ 1 回ずつ計算した
fib(&m, 10)   // 55（キャッシュから）
m.misses()    // 11 のまま

let m = Memo::new();
m.schedule(12);
m.schedule(5);
m.run_all(|_, k| k * 10)
// [(5, 50), (2, 20), (1, 10), (12, 120), (6, 60), (3, 30), (1, 10)]
m.misses()    // 6（2 回目の 1 はキャッシュにある）
```
