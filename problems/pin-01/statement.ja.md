どちらの関数も、`async` ブロックで書いたいくつかのタスクを、小さなラウンドロビン方式の実行器で動かします
（使えるのは `std` だけで、非同期ランタイムはありません）。

```rust
pub fn squares_round_robin(n: u32) -> Vec<u32>;
pub fn finish_order(delays: &[u32]) -> Vec<usize>;
```

- タスクは `yield_now()` を await して処理を譲ります。`yield_now()` は、最初に poll されたときは
  （タスクを起こしてから）`Poll::Pending` を、次に poll されたときは `Poll::Ready(())` を返します。
  これはこのままで正しく動きます。
- 実行器 `run_round_robin` はラウンド単位で動きます。各ラウンドでは、まだ終わっていないタスクを
  添字の順に 1 回ずつ poll します。すべてのタスクが終わるまでラウンドを繰り返し、終わったタスクを
  再び poll することはありません。したがって、`k` 回譲るタスクはラウンド `k + 1` で終わります。
- `squares_round_robin(n)` は、添字が `0` から `n - 1` の `n` 個のタスクを動かします。タスク `i` は
  合計に `i` を `i` 回足して `i * i` を求め、1 回足すごとに処理を譲ります。結果は各タスクの出力を
  添字の順に並べたものです。`n = 0` なら空です。
- `finish_order(delays)` は `delays` の要素ごとに 1 つのタスクを動かします。タスク `i` は
  `delays[i]` 回譲ってから終わります。結果は、タスクの添字を終わった順に並べたものです。
  同じラウンドで終わったタスクは添字の順に並べます。`delays` が空なら空です。

公開されているシグネチャは変えないでください。タスクは `async` ブロックのまま、ラウンドロビン方式の
実行器で動かしてください。

### 例

- `squares_round_robin(4)` は `[0, 1, 4, 9]` を返します。
- `finish_order(&[2, 0, 1])` は `[1, 2, 0]` を返します。タスク 1 はラウンド 1 で、タスク 2 は
  ラウンド 2 で、タスク 0 はラウンド 3 で終わります。
