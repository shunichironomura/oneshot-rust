次のコードはコンパイルが通り、手元で実行すると「それっぽく」動きます。
しかし**未定義動作（UB）**を含んでおり、Miri で実行すると UB として検出されます。

`next_id` と `reserve` は、重複してはならない ID（通し番号）を払い出します。
たとえば、複数のワーカースレッドが同時に処理するリクエストに番号を振るのに使います。

```rust
pub fn next_id() -> u64
pub fn reserve(n: u64) -> std::ops::Range<u64>
```

- `next_id` は新しい ID を 1 つ返します。
- `reserve(n)` は、連続する新しい ID を `n` 個、範囲 `start..start + n` として返します。
  `n` は `0` のこともあり、そのときは空の範囲を返します。
- 同じ ID を 2 回払い出してはいけません。`next_id` が返す ID と、`reserve` が返す範囲に含まれる ID は、
  すべてのスレッド、すべての呼び出しを通じて互いに異なります。
- 1 つのスレッドの中では、払い出す ID は、そのスレッドがそれまでに受け取ったどの ID よりも大きくなります。
- どちらの関数も、複数のスレッドから同時に呼ばれることがあります。
- 最初の ID の値は自由に決めてかまいません。`n` は 1000 以下で、オーバーフローは考えなくてかまいません。

UB を取り除いて、正しく動くようにしてください（`unsafe` を使い続けてもかまいません）。

### 例

- 1 つのスレッドで `let a = next_id(); let r = reserve(3); let b = next_id();` とすると、
  たとえば `a = 7`、`r = 8..11`、`b = 11` になります。間にほかのスレッドが ID を受け取ると値は飛びますが、
  `a < r.start`、`r.end - r.start == 3`、`r.end <= b` は常に成り立ちます。
- 3 つのスレッドを `std::thread::scope` で起動し、それぞれが `next_id` を 3 回呼びます。
  9 個の ID はすべて異なり、各スレッドの 3 個の ID は増加しています。
