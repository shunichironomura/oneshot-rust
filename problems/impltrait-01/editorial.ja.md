`impl Trait` を返す関数も、返すのは**ひとつの**具体的な型です。その型は関数の本体が決め、呼び出し側からは
「トレイトを実装している何かの型」としか見えません。「トレイトを実装している値なら何でもよい」という意味では
ないので、どの分岐も同じ型を返す必要があります。クロージャはそれぞれ固有の無名の型を持ち、見た目が同じでも
同じ型にはなりません。そのため `Filter<Copied<Iter<i32>>, {closure#1}>` と
`Filter<Copied<Iter<i32>>, {closure#2}>` は別の型で、`Copied<Iter<i32>>` はさらに別の型です。

模範解答は、分岐を 1 つの値の**中に**移しています。`keep` で `match` するクロージャを持つ `filter` を
1 つだけ作ります。このクロージャには `move` が必要です。`keep` は引数なので、借用するだけのクロージャは
関数の呼び出しより長く生きられません。`move` がないと E0373（"closure may outlive the current function"）に
なります。`Keep` は `Copy` なので、`move` で単にコピーされます。

型エラーの陰に、ロジックのバグが 1 つ隠れています。型だけを直しても、これは残ります。`%` は剰余で、
結果の符号は左側のオペランドに従います。`-3 % 2` は `-1` です。そのため `x % 2 == 1` では負の奇数を
取りこぼします。代わりに `x % 2 != 0`（または `x.rem_euclid(2) == 1`）で判定します。

### 別解

分岐はそのままにして、型を消す方法もあります。`Box<dyn Iterator<Item = i32> + '_>` は、中にどんな
イテレータが入っていても 1 つの型で、それ自身も `Iterator` を実装しているので、`impl Iterator` として
返せます。各アームをトレイトオブジェクトに変えるのは `boxed` の型注釈です。これがないと、
それぞれの `Box::new(...)` が固有の具体的な型のままになり、アームの型は食い違ったままです。
`+ '_` は、イテレータが `v` を借用していることを表します。

```rust
pub fn select(v: &[i32], keep: Keep) -> impl Iterator<Item = i32> + '_ {
    let iter = v.iter().copied();
    let boxed: Box<dyn Iterator<Item = i32> + '_> = match keep {
        Keep::Evens => Box::new(iter.filter(|x| x % 2 == 0)),
        Keep::Odds => Box::new(iter.filter(|x| x % 2 != 0)),
        Keep::All => Box::new(iter),
    };
    boxed
}
```

ボックス化すると、ヒープ確保と、要素ごとの間接呼び出しのコストがかかります。模範解答ではこれを避けています。
