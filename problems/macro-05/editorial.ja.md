`$first:expr $(, $rest:expr)* $(,)?` は、1 つの式と、それに続くカンマ区切りの 0 個以上の式、そして
あってもなくてもよい末尾のカンマにマッチします。トランスクライバーの `$( ... )*` は、マッチした
`$rest` ごとに 1 回ずつ繰り返されます。

式として使うマクロは、1 つの式に展開されなければなりません。複数の文を実行したいときはブロックに展開します。
`=> {{ ... }}` の外側の波かっこはトランスクライバーの区切りで、内側の波かっこがブロックです。
その中で宣言したローカル変数（`max`、`next`）は衛生的（hygienic）で、呼び出し側の変数とは、
名前が同じでもぶつかりません。

模範解答は各引数をちょうど 1 回ずつローカル変数に束縛し、次の値が真に大きいときだけ最大値を置き換えます。
そのため、等しい値のうち最も左のものが残ります。`let max = ...` でシャドーイングすれば `let mut` が要らず、
引数が 1 つのときに使われない `mut` の警告も出ません。思いつきやすい
`if $a > max_of!($($rest),+) { $a } else { max_of!($($rest),+) }` は残りの引数を 2 回展開するので、
副作用が 2 回起き、`Copy` でない変数はムーブした後に使うことになります。`Iterator::max` や
`std::cmp::max` は `Ord` を要求し（`f64` は実装していません）、等しい最大値が複数あると**最後**のものを返します。

### 別解

各引数を 1 回だけローカル変数に束縛すれば、`max_of!` は再帰でも書けます。再帰呼び出しは `$crate` 経由に
しなければなりません。展開結果の中のパスはマクロを呼び出した場所で解決されるので、テストのように
マクロを `use` せずパスで呼ぶモジュールでは、`max_of!(...)` とだけ書いた再帰呼び出しが見つからないからです。
`$crate` は常にマクロを定義したクレートを指します。

```rust
macro_rules! max_of {
    ($only:expr $(,)?) => {
        $only
    };
    ($first:expr, $($rest:expr),+ $(,)?) => {{
        let first = $first;
        let rest = $crate::user::max_of!($($rest),+);
        if rest > first { rest } else { first }
    }};
}
pub(crate) use max_of;
```
