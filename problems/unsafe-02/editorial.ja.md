テンプレートは、**スライス全体**を指すもう 1 つの `&mut [i32]`（`whole`）を作ったうえで、`v` も使い続けています。
`&mut` は排他的なアクセスを約束するので、同じメモリを指す 2 つの `&mut` を両方とも使える状態に保つことはできません。
最終的に呼び出し側へ渡す 2 つの半分が重ならなくても同じです。ここでは `&mut v[..mid]` が `v` 全体を一意に借用し直すことで
`whole` が無効になり、次の行で `whole` を使ったところを Miri の Stacked Borrows が検出します。

直し方は、他で使っているメモリにかかる参照を作らないことです。生ポインタを 1 つだけ取り、
それぞれの半分を**そのポインタから**、自分の担当範囲だけで作ります。
`from_raw_parts_mut(ptr, mid)` と `from_raw_parts_mut(ptr.add(mid), len - mid)` の範囲は重ならないので、
2 つの `&mut` が同じ場所を指すことはありません。

### 別解

標準ライブラリに同じ操作が安全な関数として用意されているので、関数全体を 1 行にできます。

```rust
pub fn split_in_two(v: &mut [i32], mid: usize) -> (&mut [i32], &mut [i32]) {
    v.split_at_mut(mid)
}
```

その中身もほぼ模範解答と同じで、1 つのポインタから重ならない 2 つの範囲を作っています。
