`matches_any!` のマッチャー `$($p:pat)|+` は、`|` で区切られた 1 つ以上のパターンという意味です。
Rust 2021 より前は `pat` フラグメントが最上位の `|` にマッチしなかったので、`matches!` などのマクロは
こう書かれていました。2021 エディションからは、`pat` は or パターン全体にマッチします。`1 | 4..=6` で
1 つの `pat` です。そのため、`pat` フラグメントの直後の `|` はどちらの意味か決められず、rustc は定義そのものを
拒否します（「`$p:pat` is followed by `|`, which is not allowed for `pat` fragments」）。`pat` の後に
置けるのは `=>`、`,`、`=`、`if`、`in` だけです。パターン全体を 1 つの `$p:pat` で受け取れば直ります。
今の `matches!` もそう定義されています。

`index_of!` は tt マンチャー（tt muncher）です。最後のルールが `match` で `value` を 1 回だけ評価し、
内部用の `@check` ルールをインデックス 0 から始めます。`@check` の各段階ではパターンを 1 つ試し、
マッチしなければ、残りのトークンと 1 増やしたインデックスで自分自身を呼びます。リストが空になれば `None` です。
この段階のマッチャーにある `$(, $($rest)*)?` には、フラグメント指定子がありません。マッチャーの中の
メタ変数にはすべて指定子が必要です（`$rest:tt`）。`$rest` とだけ書くのはトランスクライバーの中です。
このようなルールを呼び出すと昔からエラーでしたが、Rust 1.89 からは、使われないルールであっても
定義の時点で拒否されます（「missing fragment specifier」）。

`index_of!` の `$p:pat` はそのままにしてください。後ろが `,` なので許されており、`pat` は or パターンを
受け付けるので、`'a'..='z' | 'A'..='Z', '0'..='9'` はカンマの位置だけで区切られます。`pat_param` にすると
`char_class` がコンパイルできなくなります。

テンプレートのほかの部分はすでに正しく書かれています。`match` で `value` を束縛すると、式の一時値が
`match` の終わりまで生き続けます。再帰呼び出しは `$crate` を通しているので、テストは別のモジュールから
パスでマクロを呼べます。

### 別解

`pat_param` は `pat` の以前の意味（最上位に `|` を含まないパターン）を保っています。後ろに `|` を
置けるので、フラグメント指定子を変えるだけで元の繰り返しが使えます。

```rust
macro_rules! matches_any {
    ($value:expr, $($p:pat_param)|+) => {
        match $value {
            $($p)|+ => true,
            _ => false,
        }
    };
}
pub(crate) use matches_any;
```

`index_of!` は再帰なしでも書けます。カンマ区切りのパターンを `$($p:pat),+ $(,)?` で受け取り、
それぞれを試した結果を `bool` の配列にして、最初の `true` の位置を求めます。すべてのパターンを試しますが、
パターンを試しても副作用はなく、`value` を評価するのは 1 回だけです。

```rust
macro_rules! index_of {
    ($value:expr; $($p:pat),+ $(,)?) => {
        match $value {
            value => [$(matches!(value, $p)),+].iter().position(|&hit| hit),
        }
    };
}
pub(crate) use index_of;
```
