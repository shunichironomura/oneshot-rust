`windows(3)` はとなり合う 3 つの要素 `[v[i], v[i + 1], v[i + 2]]` を順に返すので、自分で添字を
計算する必要はありません。`i` 番目の窓の真ん中は添字 `i + 1` なので、`+ 1` が必要です。
長さが 3 未満のスライスには窓がないので、短い入力を特別扱いする必要もありません。

落とし穴は、添字を使って自分でループを書いたときにあります。

- `for i in 1..v.len() - 1` は問題なさそうに見えますが、`v` が空だと `v.len() - 1` は `usize` の
  `0 - 1` です。ジャッジはデバッグビルドと同じくオーバーフロー検査を有効にしているので、
  `attempt to subtract with overflow` でパニックします。
- `v[i - 1] < v[i]` の代わりに `v[i] - v[i - 1] > 0` で比べると、`i32::MIN` と `i32::MAX` が
  となり合ったときにオーバーフローします。値はそのまま比べてください。

### 別解

範囲の終わりがアンダーフローしないようにすれば、添字のループでも書けます。`saturating_sub` は
アンダーフローせずに `0` で止まります。

```rust
pub fn local_peaks(v: &[i32]) -> Vec<usize> {
    (1..v.len().saturating_sub(1))
        .filter(|&i| v[i - 1] < v[i] && v[i] > v[i + 1])
        .collect()
}
```
