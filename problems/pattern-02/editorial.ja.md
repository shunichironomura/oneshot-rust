タプルや `Some(..)`、構造体のパターンなど、参照パターン以外のパターンが参照にマッチすると、コンパイラは
その参照を読み飛ばし、**デフォルトの束縛モード**を `move` から `ref` に切り替えます。そこから下の束縛は
すべて借用になります。これが「マッチエルゴノミクス」です。`for (name, s) in scores` では各要素が
`&(String, u32)` なので、`name` は `&String`、`s` は `&u32` になります。

Rust 2021 では `mut` がこっそりモードを `move` に戻していたので、`(name, mut s)` の `s` はコピーされた
`u32`、`name` は `&String` のままでした。Rust 2024 では、デフォルトの束縛モードが `move` でなくなった場所に
`ref`・`mut`・`&` を書くことが禁止され、この `mut` もそれに当たります。

`mut` を消すだけだと `s` は `&u32` になり、`s += 5` はコンパイルできません。`*s += 5` は共有参照を通した
書き込みなので、これも許されません。外側の `&` を自分で書きましょう。`&(ref name, mut s)` は参照パターンで
参照そのものにマッチするので、パターンは**完全に明示的**（読み飛ばす参照がない）になり、モードは `move` の
ままで、`ref` も `mut` もまた書けるようになります。ここでの `ref` は冗長ではなく必須です。
`&(name, mut s)` だと `String` をスライスからムーブすることになり、コンパイルできません。
`cargo fix --edition` やコンパイラの提案も同じ直し方です。

### 別解

短いパターンのままにして、本体で得点をコピーして取り出す方法です。

```rust
pub fn bonus_total(scores: &[(String, u32)]) -> u32 {
    let mut total = 0;
    for (name, s) in scores {
        let mut s = *s;
        if name.len() > 3 {
            s += 5;
        }
        total += s;
    }
    total
}
```

イテレータアダプタを使えば、書き換える変数そのものがなくなります。`s + 5` は `&u32` のままでも計算できますが、
もう一方の分岐は両方の型を `u32` に揃えるために `*s` が必要です。

```rust
pub fn bonus_total(scores: &[(String, u32)]) -> u32 {
    scores
        .iter()
        .map(|(name, s)| if name.len() > 3 { s + 5 } else { *s })
        .sum()
}
```
