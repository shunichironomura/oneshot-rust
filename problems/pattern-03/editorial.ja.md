タプルなど、参照パターン以外のパターンが参照にマッチすると、コンパイラはその参照を読み飛ばし、
**デフォルトの束縛モード**を `move` から `ref` に切り替えます。そこから下の束縛はすべて借用になります。
これが「マッチエルゴノミクス」です。Rust 2024 では、パターンがこうして読み飛ばした参照より下に
`ref`・`mut`・`&` を書くことが禁止されました。

`filter` は各要素を**参照で**渡すので、クロージャが受け取るのは要素より参照が 1 つ多い
`&(usize, &u32)` です。パターン `(_, &s)` はこの外側の参照を読み飛ばしているので、その `&` は今はエラーです。
`|&(_, &s)|` と書けば 2 つの参照を両方とも明示でき、`s` は `u32` になります。逆に `&` を消すと `s` は
`&&u32` になり、`s > par` も `*s > par` もコンパイルできません（`**s > par` なら通ります）。

`initials` は最初から正しいコードです。`|&(c, _)|` は `&` から始まるので、パターンは**完全に明示的**
（読み飛ばす参照がない）で、`c` は `char` になります。ルールは「クロージャの引数に `&` を書かない」ではなく、
「パターンが読み飛ばした参照より下に `ref`・`mut`・`&` を書かない」です。同様に、`.map(|(round, _)| round)`
が受け取るのは値としての `(usize, &u32)` なので、ここでは何も読み飛ばしていません。

`cargo fix --edition` も模範解答と同じ直し方をします。パターンを完全に明示的な形にします。

### 別解

短いパターンのままにして、本体で参照外しをする方法です。

```rust
pub fn rounds_over(scores: &[u32], par: u32) -> Vec<usize> {
    scores
        .iter()
        .enumerate()
        .filter(|(_, s)| **s > par)
        .map(|(round, _)| round)
        .collect()
}
```

`filter_map` は各要素を値で受け取るので、`(round, &s)` は参照を読み飛ばしておらず、そこでは `&` を書けます。

```rust
pub fn rounds_over(scores: &[u32], par: u32) -> Vec<usize> {
    scores
        .iter()
        .enumerate()
        .filter_map(|(round, &s)| (s > par).then_some(round))
        .collect()
}
```
