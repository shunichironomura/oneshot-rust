参照を返す関数では、返す参照がどの引数を借用しているのかを示す必要があります。
ライフタイムを省略すると、コンパイラは省略規則で補います。参照の引数にはそれぞれ別のライフタイムが付き、
参照の引数がちょうど 1 つなら、返り値にもそのライフタイムが付きます（メソッドでは `&self` のライフタイムが付きます）。
`first_word` は参照の引数が 1 つなので、そのままコンパイルが通り、変更は要りません。
`strip_tag` と `pick` は 2 つある（`first` は参照ではありません）ので、コンパイラは推測せずに
E0106（missing lifetime specifier）を報告します。

`pick` は `a` と `b` のどちらを返すこともあるので、返り値が有効なのは**両方**が有効な間だけです。
2 つの引数と返り値に同じライフタイム `'a` を付けます。引数のほうが長生きしていても問題ありません。
コンパイラは、すべての引数に収まる短さの `'a` を選ぶからです。

罠は `strip_tag` です。`pick` と同じように（コンパイラのヘルプが提案するとおりに）すべての参照に `'a` を
付けると、関数単体ではコンパイルが通りますが、返り値が `tag` も借用しうると宣言したことになります。
すると呼び出し側は返り値を使う間 `tag` を生かしておく必要があり、タグを一時的な `String` で作って
返り値を使う前に破棄するハーネスは、"`tag` does not live long enough" で失敗します。
本体が返すのは常に `line` のスライスなので、返り値とライフタイムを共有するのは `line` だけです。
`tag` は省略した別のライフタイムのままにしておきます。

### 別解

2 つ目のライフタイムにも名前を付けると、`tag` が返り値と無関係であることがはっきりします。
`first_word` も、省略規則が補うライフタイムを明示して書けます。

```rust
pub fn strip_tag<'a, 'b>(line: &'a str, tag: &'b str) -> &'a str {
    match line.strip_prefix(tag) {
        Some(rest) => rest.trim_start(),
        None => line,
    }
}

pub fn first_word<'a>(s: &'a str) -> &'a str {
    s.split_whitespace().next().unwrap_or("")
}
```

`pick` に 2 つのライフタイムを使うこともできます。その場合は、`b` のライフタイムが少なくとも返り値の
ライフタイムの間は続くことを宣言します。`'b: 'a` は「`'b` は `'a` より長生きする」という意味で、
これにより `b` を `&'a str` として返せます。

```rust
pub fn pick<'a, 'b: 'a>(a: &'a str, b: &'b str, first: bool) -> &'a str {
    if first { a } else { b }
}
```
