クロージャの 3 つのトレイトは段階的な関係になっています。どのクロージャも `FnOnce` を実装します（1 回は呼べます）。
キャプチャした値を外へムーブしないクロージャは `FnMut` も実装し、さらにキャプチャした値を変更もしないものは
`Fn` も実装します。境界の強さには一長一短があります。弱い境界ほど呼び出し側は多くのクロージャを渡せますが、
本体で `f` にできることは少なくなります。そこで、本体が必要とする最小限のものだけを要求します。

- 本体は `f` を 2 回呼ぶので、`FnOnce` は使えません。1 回目の呼び出しで `f` が消費され、2 回目が
  「use of moved value: `f`」（E0382）で失敗します。
- ハーネスの番号付けのクロージャは `next` を更新するので、`Fn` も使えません。残るのは `FnMut` です。
- `FnMut` を呼ぶには `f` を可変借用する必要があるので、引数は `mut f` にします。そうしないと本体が
  「cannot borrow `f` as mutable」（E0596）で失敗します。
- 入力と出力の型は異なる（`&str` から `String`、`i32` から `bool`、`Vec<u8>` から `usize`）ので、
  型引数が `A` と `B` の 2 つ必要です。組の 2 つの要素は同じ `f` に渡すので、どちらも型 `A` です。

`map_pair(&mut record, ...)` が通るのは、`F` が `FnMut` なら `&mut F` も `FnMut` だからです。
クロージャは借用されるだけなので、もう一度渡すことができ、最後に使い終わった後は `seen` を読めます。

### 別解

引数位置の `impl Trait` は型引数の略記です。名前を付けた型引数に `where` 節で境界を書いても、ここでは同じ意味になります。

```rust
pub fn map_pair<A, B, F>(mut f: F, pair: (A, A)) -> (B, B)
where
    F: FnMut(A) -> B,
{
    (f(pair.0), f(pair.1))
}
```
