Rust 2024 では、`gen` がキーワードとして予約されました（イテレータを書くための、計画中の `gen` ブロック用です）。
`rand` クレートが `Rng::gen` を `Rng::random` に改名したのもこのためです。2024 のコードでは `gen` という語を
識別子に使えないので、定義の `pub fn gen` も、`gen_below` の中の呼び出し `self.gen()` も構文エラーになります。
ハーネスがこの名前を使うので、名前は変えられません。どちらも生識別子 `r#gen` で書きます。`r#gen` は `gen` と
同じ名前です。2021 のクレートからは今までどおり `.gen()` で呼べ、ハーネスのような 2024 のコードからは
`rng.r#gen()` と書いて呼びます。予約されたのはこの語そのものだけなので、`gen_below` や文字列の `"gen"` は
変える必要がありません。

`type` はどのエディションでもキーワードです。そのため 2021 のコードでも、フィールドはすでに `r#type` と
書かれていました。生識別子はローカル変数にも、フィールド初期化の省略記法 `Token { r#type, text: ... }` にも
使えるので、`classify` はそのままでコンパイルが通ります。

もう 1 つの変更は目立ちません。2024 より前は、`Box<[T]>` に対して `.into_iter()` を呼んでも、後方互換性のために
ボックスを借用するだけで、参照 `&T` を順に返していました（Rust 2021 では `boxed_slice_into_iter` リントの警告も
出ます）。2024 では `IntoIterator for Box<[T]>` が使われ、ボックスを消費して値そのものを順に返します。そのため
`p` は `u32` になり、`*p` はコンパイルできません（E0614）。`*` を消すだけでは足りません。`into_iter()` が
`points` をムーブするので、ループの後の `points.len()` はムーブ済みの値を使うことになります（E0382）。
`points.iter()` なら以前と同じ意味になり、`cargo fix --edition` もこう書き換えます。

### 別解

先に長さを読んでから、ボックスを消費する方法です。`for p in points` は値を順に取り出します。

```rust
pub fn score(points: Box<[u32]>) -> u32 {
    let bonus = points.len() as u32;
    let mut total = 0;
    for p in points {
        total += p;
    }
    total + bonus
}
```

イテレータを使えば、要素ごとに得点と 1 を足せます。

```rust
pub fn score(points: Box<[u32]>) -> u32 {
    points.iter().map(|p| p + 1).sum()
}
```
