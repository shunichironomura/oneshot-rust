スレッドプールは、ジョブのたびに新しいスレッドを起動する代わりに、決まった数のワーカースレッドを
動かし続けて、ジョブを渡していく仕組みです。きれいに止められるスレッドプールを書いてください。
下の骨組みはエディタに入っています。`ThreadPool` のフィールドは自由に決めてください。
必要な型や関数を追加してもかまいません。

```rust
pub struct ThreadPool { /* private */ }

impl ThreadPool {
    pub fn new(size: usize) -> ThreadPool;
    pub fn execute<F>(&self, f: F)
    where
        F: FnOnce() + Send + 'static;
    pub fn shutdown(self) -> usize;
}

impl Drop for ThreadPool { /* ... */ }
```

- `new(size)` は `size` 個のワーカースレッドを起動して、プールを返します。`size` が `0` なら
  パニックします。
- `execute(f)` はジョブ `f` をプールのキューに追加し、ジョブが始まるのを待たずにすぐに戻ります。
- どのジョブもちょうど 1 回、プールのワーカースレッドのどれかで実行されます。`execute` を
  呼んだスレッドで実行されることも、そのジョブのためだけに起動したスレッドで実行されることも
  ありません。
- ワーカーは一度に 1 つのジョブを実行します。手が空くと、いちばん長く待っているジョブを取ります
  （先入れ先出し）。待っているジョブは、ほかのワーカーが忙しい間も、手の空いたワーカーが取ります。
  そのため、サイズ `n` のプールは最大 `n` 個のジョブを同時に実行します。サイズ 1 のプールは、
  ジョブを追加された順に 1 つずつ実行します。
- 複数のスレッドが、同じプールの `execute` を同時に呼ぶことがあります。ハーネスは
  `std::thread::scope` を使って、`&ThreadPool` を複数のスレッドで共有します。
- `shutdown()` は、プールに追加されたすべてのジョブが終わるまで待ちます。キューで待っている
  ジョブも含みます。それからワーカースレッドを止めて、それらが終わるのを待ち、プールが実行した
  ジョブの数を返します。どのジョブも実行されるので、これは `execute` を呼んだ回数です。
- `shutdown` を呼ばずにプールを破棄（drop）したときも同じことをします。ただし返す数はありません。
  破棄が終わった時点で、すべてのジョブが終わっていて、すべてのワーカースレッドが終了しています。
- ジョブはパニックしません。ジョブが同じプールのほかのジョブを待つこと（たとえば `Barrier` で）は
  ありますが、ハーネスが、起こりえないことをスレッドに待たせることはありません（すべてのスレッドが
  永遠に待つと、Miri はデッドロックを報告します）。

シグネチャは変えないでください。

### 例

```rust
let pool = ThreadPool::new(2);
let total = Arc::new(AtomicUsize::new(0));
for i in 1..=3 {
    let total = Arc::clone(&total);
    pool.execute(move || {
        total.fetch_add(i, SeqCst);
    });
}
pool.shutdown()       // 3。プールは 3 個のジョブを実行した
total.load(SeqCst)    // 6 = 1 + 2 + 3
```

サイズ 1 のプールに、共有の `Vec` に `"a"`、`"b"`、`"c"` をそれぞれ追加する 3 つのジョブを渡してから、
プールを破棄します。破棄が終わると、`Vec` は `["a", "b", "c"]` です。
