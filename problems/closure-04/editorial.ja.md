`each_digit` は `f` を 2 回使います。上の桁のための再帰呼び出しに `f` を渡し、その後で最後の桁について
`f` を呼びます。値で受け取ると `f` は再帰呼び出しにムーブされ、その後の呼び出しが「borrow of moved value:
`f`」（E0382）で失敗します。テンプレートの `Fn` を `FnMut` に変えるだけでは直りません。ハーネスの
`&mut` のクロージャはその境界に合いますが、ムーブはそのまま残るからです。

ハーネスはクロージャへの `&mut` 参照を渡すので、参照のまま受け取って `f: &mut impl FnMut(u64)` とします。

- `&mut F` は `F` そのものと同じように呼べるので、`mut f` は要りません。
- `&mut` の引数が期待される場所に `f` を渡すと、ムーブではなく（`&mut *f` としての）再借用になるので、
  `f(n % 10)` のときにも `f` を使えます。呼び出し側のクロージャも借用されるだけなので、ハーネスは
  `add` を 3 回渡し、その後で `sum` を読めます。
- クロージャは `Vec` に追加したり和を更新したりするので、境界は `Fn` ではなく `FnMut` です。

コンパイラは `each_digit(n / 10, &mut f)` を提案しますが、これは本体の変更ですし、このジェネリックな
関数では通常のビルドがそもそも通りません。再帰の段ごとに新しい型 `&mut &mut ... F` で `each_digit` を
呼ぶことになり、rustc は「reached the recursion limit while instantiating」で諦めてしまいます。
（ジャッジではこの問題は検出されません。Miri は関数を実際に呼ばれたときに初めてインスタンス化し、
`u64` の桁数は高々 20 だからです。）

### 別解

名前を付けた型引数に `where` 節で境界を書いても同じ意味になります。

```rust
pub fn each_digit<F>(n: u64, f: &mut F)
where
    F: FnMut(u64),
{
    if n >= 10 {
        each_digit(n / 10, f);
    }
    f(n % 10);
}
```

`each_digit` はトレイトオブジェクトを受け取ることもできます。その場合、どのクロージャに対しても
コンパイルされる関数は 1 つだけになり、`f` の呼び出しはどれも vtable を経由します。

```rust
pub fn each_digit(n: u64, f: &mut dyn FnMut(u64)) {
    if n >= 10 {
        each_digit(n / 10, f);
    }
    f(n % 10);
}
```
