`self.cache.entry(id)` は、返された参照が使われなくなるまで `self.cache` を可変借用します。
`or_insert_with` に渡したクロージャは `&mut self` のメソッド `self.build(id)` を呼ぶので、`self` **全体**への
排他的なアクセスが必要です。そこにはすでに借用されている `self.cache` も含まれます。`build` が実際には
`self.built` しか触らないことは、コンパイラには分かりません。メソッドのシグネチャは構造体全体を借用するからです。

キャッシュの検索とラベルの作成を入れ子にせず、順番に行います。`contains_key` で確かめ、なければラベルを
作って挿入し、最後にキャッシュ内への参照を返します。

呼び出しをクロージャの外に出す（`entry` の前に `let label = self.build(id);` と書く）とコンパイルは通りますが、
毎回ラベルを作ってしまうので `built` が合わなくなります。

### 別解

エントリ API のまま、クロージャには必要なフィールドだけを借用させる方法もあります。メソッドの本体の中では
コンパイラはフィールドを別々に追跡し、クロージャも使うフィールドだけをキャプチャします。そのため、
クロージャの中で直接 `self.built += 1` と書けば問題ありません。

```rust
pub fn get(&mut self, id: u32) -> &str {
    self.cache.entry(id).or_insert_with(|| {
        self.built += 1;
        format!("item-{id}")
    })
}
```

こちらはハッシュの検索が 2 回ではなく 1 回で済みます。補助関数を残したい場合は、`&mut self` ではなく
`&mut usize`（など必要なフィールドだけ）を受け取るようにします。
