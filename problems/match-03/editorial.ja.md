`match` は**網羅的**でなければなりません。コンパイラは型とパターンだけから、どの値にもいずれかのアームが
マッチすることを証明できる必要があり、できなければ E0004 を報告します。コードを実行するわけではないので、
ガードの条件や、関数がどんな値を返すかは考慮しません。5 つの `match` はそれぞれ別の理由で網羅的でなく、
正しい直し方もそれぞれ違います。

- `digits_label`：`100..255` は `for` ループの `0..10` と同じく終端を含まない範囲なので、254 で終わり、
  `255` が漏れています。`100..=255` か、`u8::MAX` まで続く `100..` と書きます。
- `sign_word`：`if` の付いたアームはマッチしないかもしれないので、コンパイラは網羅性を調べるときにガードを
  無視します。見えているのはパターン `0` だけです。`..0` と `1..` のような範囲パターンなら、同じ内容を
  コンパイラが確かめられる形で書けます。
- `quadrant`：`signum()` が返すのは `i32` で、コンパイラはそれが必ず `-1`、`0`、`1` のどれかだとは知らないので、
  `(2, 5)` などが漏れているように見えます。`x.cmp(&0)` が返す `Ordering` はバリアントがちょうど 3 つの列挙型
  なので、7 つのアームで網羅的になります。ここでは `signum` の 7 つのアームの後に `_ => unreachable!()` を
  足しても正解です。ほかの値は実際には現れないからです。
- `grade`：`score` は `u32` なので、`101` 以上が漏れています。今度は何でも受けるアームを足すと**間違い**です。
  `_ => 'F'` では加点のある `130` が `'F'` になり、`_ => unreachable!()` ではパニックします。問題文では
  そうした点数も `'A'` なので、最初のアームを `90..` にします。
- `parse_answer`：`&str` の値は無限にあるので、文字列の `match` には必ず何でも受けるアームが必要です。
  ここでは `_ => None` です。

`_ => ...` を足せば E0004 は必ず消えますが、その場合はもうコンパイラが代わりに確かめてはくれません。
書く前に、実際にどの値がそこに来て、何を返すべきかを考えてください。

### 別解

テンプレートの書き方をなるべく残し、安全なところでだけ何でも受けるアームを使う直し方もあります。
`grade` の `_ => 'F'` が安全なのは、高い点数を先に `90..` がすべて受け取るからです。`parse_answer` は
模範解答と同じです。

```rust
pub fn digits_label(n: u8) -> &'static str {
    match n {
        0..10 => "one digit",
        10..100 => "two digits",
        100..=255 => "three digits",
    }
}

pub fn sign_word(n: i32) -> &'static str {
    match n {
        x if x < 0 => "negative",
        0 => "zero",
        _ => "positive",
    }
}

pub fn quadrant(x: i32, y: i32) -> &'static str {
    match (x.signum(), y.signum()) {
        (1, 1) => "I",
        (-1, 1) => "II",
        (-1, -1) => "III",
        (1, -1) => "IV",
        (0, 0) => "origin",
        (0, _) => "y-axis",
        (_, 0) => "x-axis",
        _ => unreachable!("signum() is always -1, 0 or 1"),
    }
}

pub fn grade(score: u32) -> char {
    match score {
        90.. => 'A',
        80..=89 => 'B',
        70..=79 => 'C',
        60..=69 => 'D',
        _ => 'F',
    }
}
```

`quadrant` は `(x, y)` を範囲パターンで直接マッチすることもできます。先に軸の上の点を片付ければ、
残りは 4 つの象限だけになり、コンパイラにもそれがわかります。

```rust
pub fn quadrant(x: i32, y: i32) -> &'static str {
    match (x, y) {
        (0, 0) => "origin",
        (0, _) => "y-axis",
        (_, 0) => "x-axis",
        (1.., 1..) => "I",
        (..0, 1..) => "II",
        (..0, ..0) => "III",
        (1.., ..0) => "IV",
    }
}
```
