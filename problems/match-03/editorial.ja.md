`match` は**網羅的**でなければなりません。コンパイラは型とパターンだけから、どの値にもいずれかのアームが
マッチすることを証明できる必要があり、できなければ E0004 を報告します。コードを実行するわけではないので、
関数がどんな値を返すかは考慮しません。`signum()` が返すのは `i32` で、コンパイラはそれが必ず `-1`、`0`、`1` の
どれかだとは知らないので、`(2, 5)` などが漏れているように見えます。

`x.cmp(&0)` が返す `Ordering` はバリアントがちょうど 3 つの列挙型なので、7 つのアームで網羅的になります。
ここでは `signum` の 7 つのアームの後に `_ => unreachable!()` を足しても正解です。ほかの値は実際には
現れないからです。

`_ => ...` を足せば E0004 は必ず消えますが、その場合はもうコンパイラが代わりに確かめてはくれません。
書く前に、実際にどの値がそこに来て、何を返すべきかを考えてください。

### 別解

テンプレートの書き方をなるべく残し、`signum` のまま何でも受けるアームを足す直し方もあります。ここでは安全です。

```rust
pub fn quadrant(x: i32, y: i32) -> &'static str {
    match (x.signum(), y.signum()) {
        (1, 1) => "I",
        (-1, 1) => "II",
        (-1, -1) => "III",
        (1, -1) => "IV",
        (0, 0) => "origin",
        (0, _) => "y-axis",
        (_, 0) => "x-axis",
        _ => unreachable!("signum() is always -1, 0 or 1"),
    }
}
```

`quadrant` は `(x, y)` を範囲パターンで直接マッチすることもできます。先に軸の上の点を片付ければ、
残りは 4 つの象限だけになり、コンパイラにもそれがわかります。

```rust
pub fn quadrant(x: i32, y: i32) -> &'static str {
    match (x, y) {
        (0, 0) => "origin",
        (0, _) => "y-axis",
        (_, 0) => "x-axis",
        (1.., 1..) => "I",
        (..0, 1..) => "II",
        (..0, ..0) => "III",
        (1.., ..0) => "IV",
    }
}
```
