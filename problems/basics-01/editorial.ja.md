どのうっかりも 1 語か 1 文字で直せますが、コンパイラは 5 つ全部を一度には教えてくれません。

1. **`const` には型が必要です。** `let` と違って、`const`（や `static`）のアイテムは型を推論しないので、
   `const BASE = 10;` はエラーになります。型は `u64` でなければなりません。`BASE` は `n: u64` と
   比較され、`rest % BASE` でも使われていて、Rust は整数型どうしを暗黙に変換しないからです。
   コンパイラは整数リテラルの既定の型である `: i32` を提案しますが、それに従うと新しい型エラーが
   出るだけです。
2. **引数はイミュータブルです。** 引数は `let n` と同じ束縛なので、`n = sum` はエラーになります。
   引数リストに `mut n: u64` と書くか（関数の型は変わりません）、本体の最初で `let mut n = n;` と
   シャドーイングします。ループの中で `let n = sum;` と書くとコンパイルは通りますが、繰り返しの
   終わりごとに消える新しい `n` を宣言するだけです。条件 `n >= BASE` は元の値を見続けるので、
   ループが終わりません。
3. **`n;` は文です。** 関数は最後の式の値を返します。この式にはセミコロンを付けません。`n;` と書くと
   本体は文で終わり、値は `()` になります。
4. **`if` の分岐はすべて同じ型でなければなりません。** 3 つの分岐は `&str` で、最後の 1 つだけが
   `String` です。リテラルを `.to_string()`（または `String::from`）で `String` にします。そうすれば
   `if` をそのまま関数の最後の式にできます。
5. **`break` は値を持てます。** `loop` は式で、その値は `break value` で決まります。値のない `break;`
   の値は `()` なので、`break x;` と書く必要があります。

最初のコンパイルで報告されるエラーは 4 つだけです。イミュータブルな `n` への代入を検出するのは
借用チェッカーで、借用チェッカーは型検査を通った関数しか調べません。`digital_root` は型のない `BASE` を
使っていて、`n;` で終わっているので、まだ型検査を通りません。コンパイラが示した箇所だけを直すと、
もう 1 回提出することになります。

### 別解

うっかりの一部は、書き方を変えればそもそも起きません。2 つの余りの組で `match` すれば FizzBuzz の
規則をそのまま書けますし、次の倍数はループを使わずに計算できます。`limit / step * step` は `limit`
以下で最大の `step` の倍数なので、答えはそれより `step` だけ大きい数です。

```rust
pub fn fizz_label(n: u32) -> String {
    match (n % 3, n % 5) {
        (0, 0) => "FizzBuzz".to_string(),
        (0, _) => "Fizz".to_string(),
        (_, 0) => "Buzz".to_string(),
        _ => n.to_string(),
    }
}

pub fn first_multiple_above(step: u64, limit: u64) -> u64 {
    (limit / step + 1) * step
}
```

数字根には公式もあります。ある数とその各桁の和は 9 で割った余りが等しいので、`n > 0` なら結果は
`1 + (n - 1) % 9` です。`0` だけは別の分岐が必要です（`n - 1` がアンダーフローするため）。

```rust
pub fn digital_root(n: u64) -> u64 {
    if n == 0 { 0 } else { 1 + (n - 1) % 9 }
}
```
