どのうっかりも小さな修正で直せますが、コンパイラは 3 つ全部を一度には教えてくれません。

1. **`const` には型が必要です。** `let` と違って、`const`（や `static`）のアイテムは型を推論しないので、
   `const BASE = 10;` はエラーになります。型は `u64` でなければなりません。`BASE` は `n: u64` と
   比較され、`rest % BASE` でも使われていて、Rust は整数型どうしを暗黙に変換しないからです。
   コンパイラは整数リテラルの既定の型である `: i32` を提案しますが、それに従うと新しい型エラーが
   出るだけです。
2. **引数はイミュータブルです。** 引数は `let n` と同じ束縛なので、`n = sum` はエラーになります。
   引数リストに `mut n: u64` と書くか、本体の最初で `let mut n = n;` とシャドーイングします。
   `mut n: u64` と書いてもシグネチャは変わりません。引数の `mut` は関数の中の束縛 `n` を
   ミュータブルにするだけで、関数の型には含まれず、型は `fn(u64) -> u64` のままです。引数は値渡し
   なので呼び出し側からは区別できず、rustdoc もこの `mut` を表示しません。ループの中で `let n = sum;` と書くとコンパイルは通りますが、繰り返しの
   終わりごとに消える新しい `n` を宣言するだけです。条件 `n >= BASE` は元の値を見続けるので、
   ループが終わりません。
3. **`n;` は文です。** 関数は最後の式の値を返します。この式にはセミコロンを付けません。`n;` と書くと
   本体は文で終わり、値は `()` になります。

最初のコンパイルで報告されるエラーは 2 つだけです。イミュータブルな `n` への代入は借用チェッカーが
検出しますが、借用チェッカーは型検査を通った関数しか調べません。`digital_root` は型のない `BASE` を
使っていて、`n;` で終わっているので、まだ型検査を通りません。コンパイラが示した箇所だけを直すと、
もう 1 回提出することになります。

### 別解

数字根には公式もあります。ある数とその各桁の和は 9 で割った余りが等しいので、`n > 0` なら結果は
`1 + (n - 1) % 9` です。`0` だけは別の分岐が必要です（`n - 1` がアンダーフローするため）。

```rust
pub fn digital_root(n: u64) -> u64 {
    if n == 0 { 0 } else { 1 + (n - 1) % 9 }
}
```
