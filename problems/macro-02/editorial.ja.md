この構文の値は、どれも 1 つのトークンツリーです。`null`、`true`、`3`、`"s"` は 1 つのトークンで、
`[...]`、`{...}`、`(...)` は中身が何であってもそれぞれ 1 つのグループです。そのため、ルール
`[$($element:tt),* $(,)?]` は配列を最上位のカンマで区切り、ルール `{$($key:literal : $value:tt),* $(,)?}` は
オブジェクトをペアに分けます。各要素はもう一度 `json!` に渡され、入れ子の配列やオブジェクトはそこで処理されます。
ほかの式をかっこで囲む必要があるのもこのためです。`-1` や `x - 7` は複数のトークンツリーですが、
`(x - 7)` は 1 つです。

ここでは `expr` フラグメントは使えません。`{ "a": 1 }` は Rust の式ではなく、`macro_rules!` はフラグメントの
パースに失敗すると、次のルールを試さずにエラーにします。さらに、`expr` として捕まえたフラグメントは、
別のマクロ呼び出しに渡すと中身の見えない（不透明な）ものになります。`json!($element)` と渡しても
`(null)` や `([...])` のルールにはもうマッチしないので、`[true, null]` は最後のルールまで素通りして
`Json::from([true, null])` になります。トークンでマッチできるのは `tt`、`ident`、`lifetime` の
フラグメントだけです。キーにも `expr` は使えません。`expr` フラグメントの後に置けるのは `=>`、`,`、`;` だけなので、
`$key:expr : $value:tt` というマッチャーがあると、マクロの定義そのものがコンパイルできません。
`literal` と `tt` にはこの制限はありません。

ルールは上から順に試され、最初にマッチしたものが使われます。`$other:tt` は `null`、`[...]`、`{...}` を含めて
どんな値にもマッチするので、最後に置かなければなりません。`(null)` より上にあると、`json!(null)` は
`Json::from(null)` になり、「cannot find value `null` in this scope」というエラーになります。

最後のルールでは、リテラルの種類ごとに場合分けする必要はありません。用意された実装により、`Json::from` は
`true`、`3`（整数を受け取る実装は `From<i32>` だけです）、`2.5`、`"s"`、かっこで囲んだ式のどれでも変換でき、
`Json` は標準ライブラリの `impl<T> From<T> for T` で変換されます。各要素は `vec![...]` の要素 1 つになり、
これらは左から順に評価されるので、どの式も書かれた順にちょうど 1 回評価されます。

展開結果は、マクロを呼び出した場所で解決されます。テストは `Json` も `json` も `use` していないので、
展開結果では型を `$crate::user::Json` と書き、自分自身を `$crate::user::json!` として呼び出します。
`json!(...)` とだけ書くと「cannot find macro `json` in this scope」になります。
`::std::vec!` や `::std::string::String` と絶対パスで書くのも同じ理由で、呼び出し側に独自の `vec` や
`String` があっても動くようにするためです。

### 別解

値の種類ごとにルールを書く方法です。`(($e:expr))` は 1 つの式をかっこで囲んだグループにマッチし、
かっこを取り除きます（配列のルールでは、このグループも 1 つのトークンツリーです）。`$lit:literal` は
数値リテラルと文字列リテラル、それに `true` と `false` にもマッチします。これらのルールは重ならないので
順番は関係なく、かっこで囲んでいない `x` のような式は「no rules expected `x`」として報告されます。

```rust
macro_rules! json {
    (null) => {
        $crate::user::Json::Null
    };
    ([$($element:tt),* $(,)?]) => {
        $crate::user::Json::Arr(::std::vec![$($crate::user::json!($element)),*])
    };
    ({$($key:literal : $value:tt),* $(,)?}) => {
        $crate::user::Json::Obj(::std::vec![
            $((::std::string::String::from($key), $crate::user::json!($value))),*
        ])
    };
    (($e:expr)) => {
        $crate::user::Json::from($e)
    };
    ($lit:literal) => {
        $crate::user::Json::from($lit)
    };
}
pub(crate) use json;
```
