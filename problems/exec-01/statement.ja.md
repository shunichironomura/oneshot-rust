複数のタスクを現在のスレッドで実行する小さなエグゼキュータを書いてください。次にどのタスクを
ポーリングするかは、ウェイカー（waker）を使って決めます。下の骨組みはエディタに入っています。
`Executor` のフィールドは自由に決めてください。必要な型を追加してもかまいません。

```rust
pub struct Executor { /* private */ }

impl Executor {
    pub fn new() -> Self;
    pub fn spawn(&mut self, fut: impl Future<Output = ()> + 'static);
    pub fn run(&mut self) -> usize;
    pub fn pending(&self) -> usize;
}
```

- `new` はタスクを持たないエグゼキュータを作ります。`spawn` は `fut` を実行するタスクを追加します。
  タスクをポーリングはしませんが、追加したばかりのタスクは「実行可能」です。
- `run` は、実行可能なタスクのうち最も早く実行可能になったもの（先入れ先出し）を取り出して
  1 回ポーリングし、これを実行可能なタスクがなくなるまで繰り返します。ポーリングした回数を
  返します（実行可能なタスクがなければ `0`）。
- タスクは `run` に取り出された時点で実行可能でなくなります。再び実行可能になるのは、
  そのタスクのウェイカーが `wake` か `wake_by_ref` で起こされたときだけです。タスクの
  ウェイカーとは、そのタスクのいずれかのポーリングで渡された `Context` のウェイカーと、
  その複製です。ウェイカーは、どのポーリングの最中にも（そのタスク自身のポーリングも含む）、
  `run` から戻った後にも、どのスレッドからでも起こされることがあります。
- すでに実行可能なタスクを起こしても何も起きません。次のポーリングまでに何度も起こされた
  タスクも 1 回だけポーリングし、その順番は最初に起こされたときの位置です。
- ポーリングで `Poll::Ready` を返したタスクは終了しています。その Future はすぐに破棄し、
  二度とポーリングしません。終了したタスクを起こしても何も起きません。
- `pending` は、追加したタスクのうち終了していないものの数を返します。それらのタスクは
  エグゼキュータと一緒に破棄されます。
- Future は `Send` とは限りません。ハーネスのタスクは `Rc<RefCell<...>>` の値を持っています。
  ウェイカーはエグゼキュータより長く生きることがあり、そのときに起こしても何も起きません
  （パニックもしません）。

### 例

- タスク A は `"a1"` を記録し、`wake_by_ref` で自分を起こして `Pending` を返します。
  次のポーリングで `"a2"` を記録して終了します。タスク B は `"b1"` を記録して終了します。
  A、B の順に追加すると、`run()` は `3` を返し、記録は `["a1", "b1", "a2"]`、`pending()` は
  `0` になります。
- タスク C は自分のウェイカーの複製を共有の置き場所に入れ、何も起こさずに `Pending` を
  返します。次のポーリングで終了します。C を追加すると、`run()` は `1` を返し、`pending()` は
  `1` です。C を起こしたものはないので、もう一度 `run()` を呼ぶと `0` を返します。置き場所の
  ウェイカーを起こすと、`run()` は `1` を返し、`pending()` は `0` になります。
