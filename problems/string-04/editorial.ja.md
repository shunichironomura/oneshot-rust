`&str` は UTF-8 のバイト列の中の**バイト**単位の位置でスライスします。1 文字は 1〜4 バイトです。
そのため `&s[s.len() - n..]` の `n` は文字数ではなくバイト数で、位置が文字の途中に当たるとき
（`byte index 2 is not a char boundary; it is inside 'é'`）や `n` が `s.len()` より大きいときはパニックします。
まず文字数を正しいバイト位置に直し、それからスライスする必要があります。

`char_indices` は各文字を、その文字が始まるバイト位置と一緒に返します。`last_chars` は `rev()` で
後ろからたどり、たどった `n` 文字のうち最後の文字が末尾部分の始まりになります。文字が `n` 個より少なければ
先頭の文字までたどるので、`s` 全体を取ります。`take(n).last()` なら `n = 0` も扱えます。何もたどらないので、
`map_or(s.len(), ...)` により結果は `s` の末尾にある空のスライスになります。つい書きたくなる
`rev().nth(n - 1)` は、このとき `0 - 1` が `usize` でオーバーフローしてパニックします。

参照の引数が 1 つなので、ライフタイムの省略規則により、返す `&str` は `s` に結び付きます。`s` をスライスする
だけでよく、何もコピーしません。空の結果ならリテラルの `""` でも値は同じですが、指している場所が違います。
そのため、ここでは空の結果も `s` をスライスして作っています。

### 別解

先に文字数を数えて、末尾 `n` 文字以外を読み飛ばす方法でも書けます。`n` が文字数より大きいとき、
`saturating_sub` はアンダーフローせずに 0 を返します。読み飛ばす部分がどこで終わるかは `nth(skip)` で求まります。

```rust
pub fn last_chars(s: &str, n: usize) -> &str {
    let skip = s.chars().count().saturating_sub(n);
    let start = s.char_indices().nth(skip).map_or(s.len(), |(i, _)| i);
    &s[start..]
}
```

末尾の `n` 文字の `len_utf8` を足し合わせれば、末尾部分のバイト数が直接求まります。
`n = 0` なら合計は 0 なので、`&s[s.len()..]` を返します。

```rust
pub fn last_chars(s: &str, n: usize) -> &str {
    let len: usize = s.chars().rev().take(n).map(char::len_utf8).sum();
    &s[s.len() - len..]
}
```
