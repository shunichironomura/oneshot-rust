`$t:tt` でマッチすると、`(b c)` のようなグループ全体が 1 つのトークンツリーになります。模範解答は
トークンツリーを 1 つずつはがし、そのたびに 1 を足します。もっと短い `0usize $(+ 1)*` は「attempted to
repeat an expression containing no syntax variables」で拒否されます。トランスクライバーの繰り返しの中には、
マッチャーのメタ変数がなければならないからです。

`count!` は定数式でなければならないので、`vec![...].len()` は使えません。`vec!` はヒープにメモリを
確保しますが、定数の中ではそれができないからです。`1usize + $crate::user::count!($($tail)*)` なら
定数式になります。トークンツリー 1 つにつき再帰が 1 段深くなりますが、再帰の上限は既定で 128 なので、
この問題には十分です。

展開結果の中のパスはマクロを呼び出した場所で解決され、マクロの名前も同じです。`macro_rules!` のマクロを
名前だけで呼べるのは、定義より後ろ（同じモジュールかその子モジュール）か、`use` した場所だけです。
テストが `crate::user::count!` とパスで呼ぶと、展開結果の中の再帰呼び出し `count!(...)` はテストの
モジュールで探され、見つかりません（「cannot find macro `count` in this scope」）。`$crate` は常にマクロを
定義したクレートを指すので、`$crate::user::count!` ならどこからでも呼べます。

### 別解

再帰を使わない `count!` です。各トークンツリーを `stringify!` で文字列にし、スライスの長さを求めます。
`<[&str]>::len` は `const fn` です。代わりに `[...].len()` と書くと、空の配列の要素の型がわからないので、
`count!()` でコンパイルが通りません。

```rust
macro_rules! count {
    ($($t:tt)*) => {
        <[&str]>::len(&[$(stringify!($t)),*])
    };
}
pub(crate) use count;
```
